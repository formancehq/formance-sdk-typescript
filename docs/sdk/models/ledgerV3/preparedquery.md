                                                                                                                                                         | Recursive filter expression using the Formance query DSL (aligned with the v2 API). Each node is an object with **exactly one** top-level `$`-prefixed operator key.<br/><br/>Combinators:<br/>- `{"$and": [QueryFilter, ...]}` — all sub-filters must match (non-empty).<br/>- `{"$or":  [QueryFilter, ...]}` — at least one sub-filter matches (non-empty).<br/>- `{"$not": QueryFilter}` — negates a single sub-filter.<br/><br/>Leaf conditions are a single-key operator whose value is a `{ "<field>": <value> }` map with exactly one field:<br/>- `{"$match": {"<field>": <value>}}` — equality; for `address`/`source`/`destination`<br/><br/><br/>  a trailing `:` means prefix match, otherwise exact.<br/><br/>- `{"$gt"\|"$gte"\|"$lt"\|"$lte": {"<field>": <value>}}` — range bound. A closed<br/><br/><br/>  range is expressed as an `$and` of a lower and an upper bound on the same field.<br/><br/>- `{"$exists": {"metadata": "<key>"}}` — the metadata key is present.<br/>- `{"$exists": {"asset": "<assetRef>"}}` — the account has ever held the asset<br/><br/><br/>  (`assetRef` is `BASE` or `BASE/PRECISION`, e.g. `USD/2`). Requires a READY<br/>  `account-asset` index.<br/><br/><br/>Supported fields: `metadata[<key>]`, `address`, `source`, `destination`, `reference`, `reverted` (bool), `ledger`, `id`, `timestamp`, `insertedAt`, `revertedAt`, `logId`, `date`. Not every field applies to every query target; a field that does not apply is rejected. The numeric built-ins (`id`, `timestamp`, `insertedAt`, `revertedAt`, `logId`, `date`) are **range-only** — use `$gt`/`$gte`/`$lt`/`$lte`; `$match` on them is rejected. The log-only fields (`logId`, `date`, `ledger`) are valid only when the prepared query targets `LOGS`; they are rejected on `ACCOUNTS` and `TRANSACTIONS` targets.<br/><br/>A value is either a JSON literal or a parameter reference `{"$param": "<name>"}`, resolved at prepared-query execution time. A JSON `null` in value position is rejected. uint64 fields (`id`, `timestamp`, `insertedAt`, `revertedAt`, `logId`, `date`) are carried as decimal strings to stay lossless above 2^53. The date-semantic fields (`timestamp`, `insertedAt`, `revertedAt`, `date`) additionally accept an RFC3339 timestamp string (e.g. `{"$gte":{"date":"2023-11-14T22:13:20Z"}}`), coerced to the same Unix microseconds as the raw form; a value before the Unix epoch (1970-01-01) is rejected. |
